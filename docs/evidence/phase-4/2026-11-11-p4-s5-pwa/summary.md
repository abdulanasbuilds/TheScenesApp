# P4-S5 evidence — PWA / installability and low-bandwidth shell (code/local)

**Date:** 2026-11-11
**Slice:** P4-S5 — PWA/installability and low-bandwidth shell
**Approval:** ADR-044 (code/local; remote actions NONE)
**Target:** local code, generated icons and a built Worker artifact. No deployment. No push
subscription. No provider contacted.

## Implemented

- `public/manifest.webmanifest`: app identity (`name`, `short_name`, `id`, `start_url`, `scope`),
  `display: standalone`, theme/background colours and four owned icons (192, 512, 512 maskable,
  180 apple-touch).
- `public/icons/*.png`: generated by `scripts/generate-pwa-icons.ts` from the project brand (no
  third-party asset copied).
- `public/offline.html`: a small, dependency-free generic offline shell. It contains no user data and
  no secrets.
- `public/sw.js`: a deliberately narrow service worker (see the guarantees below).
- `src/features/pwa/pwa-experience.tsx`: dismissible, user-initiated install guidance (standard
  `beforeinstallprompt` flow plus explicit iOS "Add to Home Screen" guidance) and an update banner that
  applies a new worker only when the user chooses **Reload**.
- `src/routes/__root.tsx`: manifest/theme-color/apple-touch icon links and `<PwaExperience />`.

## Service-worker guarantees

| Rule | Behaviour |
| --- | --- |
| Cacheable paths | only `/assets/*`, `/icons/*` prefixes |
| Cacheable exact files | `/offline.html`, `/manifest.webmanifest` |
| Never cached | `/_server`, `/api`, `/notifications`, `/settings`, `/dashboard` (defence in depth) |
| Navigations | always go to the network; on failure the generic offline shell is shown, never a cached HTML document |
| Cross-origin requests | never intercepted |
| Non-GET requests | never intercepted |
| Stored responses | same-origin `basic` and `ok` only |
| Registration scope | production builds only (`import.meta.env.PROD`); development and the fixture suite are never served from a stale cache |
| Activation | a new worker waits until the page asks (`SKIP_WAITING`), so it never swaps code mid-session |
| Cache versioning | one `thescenes-pwa-v1-static` cache; other caches are deleted on activate |

The worker caches **no** HTML document, no authenticated response and no API/server-function response.
Installing the PWA therefore does not create a privacy or staleness risk for private content.

## Notes on the fixture run

The final full fixture run passed cleanly (32 passed / 16 skipped / 0 failed). During this work the
suite twice reported a single unrelated test failing with `net::ERR_ABORTED` — once on the tablet
`/pricing` navigation and once on the desktop `/reset-password` navigation. Each passed on an isolated
rerun and the final full run passed with no retries, consistent with the known local Vite dev-server
navigation flake. CI uses `retries: 2` with `failOnFlakyTests`, so a genuinely flaky run cannot pass
silently in CI.

The 16 skips are the expected connected-mode browser tests (`connected-public.spec.ts` and the
`route-contract.spec.ts` cases that require a configured backend); they are declared skips in fixture
mode, not failures.

## Security / privacy review summary

- The worker never caches HTML, navigation responses, credentials or API responses.
- The offline shell contains no user data and no secrets.
- Icons are project-owned; no external asset was copied.
- Install and update prompts are dismissible and user-initiated; no unsolicited notification is
  requested.
- Web Push (P4-S6) remains **not approved and not implemented**; the integration report shows it
  `disabled`.
- Critical findings: 0. High findings: 0.

## Not run / not authorized

- No deployment; the worker is never registered in a development or fixture run.
- No VAPID key pair and no push subscription (P4-S6 not approved).
- No Lighthouse/installability audit was run in this environment; that is a deployment-time check.
- ADR-041 Wave 5 capacity/recovery remains deferred.

## Rollback

Remove the manifest/icon links and `<PwaExperience />` from `src/routes/__root.tsx` and delete
`public/{manifest.webmanifest,sw.js,offline.html,icons/*}` and `scripts/generate-pwa-icons.ts`. A
previously installed client can unregister the worker; the app then runs as an ordinary web page.
