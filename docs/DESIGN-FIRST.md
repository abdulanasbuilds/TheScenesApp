# The Scenes — Design-First System

## Hard gate

The application must be designed as a coherent system before production backend integration.

## Workflow

1. Product context
2. Business/user job
3. Information architecture
4. Interaction model
5. Visual direction
6. Multiple variants
7. Local preview
8. Comparison
9. Direction selection
10. Component system
11. Responsive/mobile design
12. Accessibility review
13. Frontend implementation
14. Visual QA

## Required variants

The first major design task must produce multiple credible directions for the complete product, not just the landing page.

At minimum compare:

- public landing;
- discovery/explore;
- authenticated Home;
- community;
- course/classroom;
- teacher/creator workspace;
- dashboards etc.

All variants must preserve the same product requirements so the comparison is meaningful.

## Required surfaces

### Marketing

Landing, pricing, become-a-teacher, about, public discovery, category pages.

### Learner

Onboarding, Home, Explore, category, course, lesson/classroom, project, community, events, workflow/resource, profile, settings, notifications.

### Teacher/Creator

Application, onboarding, dashboard, course builder, lesson builder, events/live, workflow/product publishing, audience/students, reviews, earnings, analytics, settings.

### Admin

Overview, moderation, reports, categories, creator approval, users, content, policy, system settings.

## Design language

Aim for:

- calm;
- editorial;
- practical;
- human;
- distinctive.

Avoid:

- generic neon,purple and trending AI branding;
- gratuitous glassmorphism;
- cloned competitor layouts;
- decoration without functional purpose;
- desktop-first dashboards squeezed onto phones.

## Assets

Visual assets used for production must have known provenance or be created/owned appropriately.

Do not treat external screenshots as production assets.

## Landing page

The Scenes has a real marketing landing page.

Authenticated discovery/home is a separate experience.
